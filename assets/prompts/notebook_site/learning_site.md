# Gemini Notebook 學習互動網頁提示詞（make me a site）

> **用途**：由本專案透過 Gemini Notebook 對話（只勾選指定來源）送出，產生「互動＋視覺化、不省略細節」的學習網頁；
> 網頁會存進 Studio（類型代碼 10，`text/html` 檔），再由本專案下載到 `03 Notes/NotebookLM/<講次>/`。
> **兩個版本**：A＝單一章節（只勾選該講來源）；B＝整本書／整門課（勾選全部來源）。
> **第一行 `make me a site` 是觸發網頁生成的關鍵字，必須保留英文。** `{{…}}` 由程式填入。
>
> 設計依據：
> 1. Gemma 官方教學頁（gemma.ai/learn/how-llms-work）的做法——分階段導覽、每段先說「為什麼」、可操作的模擬器、
>    完整算例、每段「重點」與銜接句、標示「示意 vs. 真實數據」。
> 2. 學習科學——主動提取、控制認知負荷、交錯練習、立即回饋、圖文雙重編碼、後設認知。
>    （Gemma 教學頁沒有自我檢核，這裡另外補上。）

## A. 單一章節版

make me a site

請根據我勾選的來源，為「{{課程名稱}}」第 {{講次}} 講「{{章名}}」製作一個**互動學習網頁**。讀者是{{讀者}}。全站使用**繁體中文**；專有名詞第一次出現時以**粗體**標示並附英文原文與一句白話解釋，例如「**效度**（validity）：測量是否真的量到想量的東西」。

### 一、內容原則（最重要）

1. **只用勾選的來源**：每個定義、例子、數據、研究、公式都來自來源，並標出處（章節或頁碼）。來源沒寫的寫「來源未說明」，不要自行補充。
2. **不省略細節**：原文每個標題與小標題都要出現，保留其下所有重點、例子、研究案例、數據、表格、公式與注意事項；內容多就用分頁、摺疊或「展開更多」，**絕不刪減**。
3. **保留原文順序與精確度**：數字、名稱、步驟照原文；同時給「白話說明」與「正式定義」，白話不可改變原意。
4. **示意要標示**：凡是為了說明而簡化的圖或模擬，用「⚠ 示意」標籤標出，和來源中的真實數據區分。

### 二、網頁結構

1. **開場**：章名、一句話說明這章要解決什麼問題、預估學習時間、3–6 條學習目標（可勾選）。兩個按鈕：「開始導覽」（逐段翻頁模式，可用 ← → 鍵切換、Esc 離開）與「瀏覽全文」。頁面固定顯示目錄與進度（例如「第 2 / 6 段」）。
2. **課前三題**：測先備知識或直覺，答完立即顯示解析，並建議「答錯的話先讀第幾段」。
3. **全章地圖**：一張可點擊的流程圖或概念關係圖，標出各段之間的關係（屬於、導致、對比、先後）；點節點跳到該段。
4. **分段內容（依原文順序，每段都包含）**：
   - **為什麼要學這段**：先提出這段要解決的問題或疑問。
   - **說明**：重點摘要＋「展開完整說明」（保留原文全部細節）；用一個貼切的比喻幫助理解，但比喻後要回到正式說法。
   - **互動視覺化**：至少一個可操作的元件（見第三部分），旁邊一行操作說明。
   - **完整算例／案例走一遍**：拿原文的例子或研究，從頭到尾逐步走完，每一步顯示中間結果。
   - **常見誤解**：「你可能以為… → 其實…」翻卡。
   - **即時檢核**：1–2 題，作答後立即顯示對錯、解析，以及錯誤選項為什麼錯。
   - **重點**：一句話總結，並用一句話銜接「下一段要解決什麼」。
5. **整合練習**：情境應用題（給案例判斷該用哪個概念或方法）、拖放配對（術語↔定義、概念↔例子）、排序題（流程步驟）、易混淆概念比較（可切換比較面向）。
6. **總整理**：一頁重點摘要表（可列印）、中英詞彙表（可搜尋，附定義與出處）、所有公式與表格彙整。
7. **期末自測**：10 題，混合記憶、理解、應用、分析，題目打散；每題立即回饋（答案、解析、出處段落連結）；結束時顯示分數與「建議複習的段落」。
8. **反思與下一步**：3 個後設認知問題、1–5 信心自評，依自評給下一步建議。

### 三、互動與視覺化（依內容類型選擇，不要純裝飾）

- 流程／步驟 → 逐步點擊或自動播放的流程圖，每步顯示說明與注意事項。
- 變項關係／公式／數據 → **模擬器**：用滑桿或輸入框改變數值，即時更新圖表與結果（例如改變樣本數看信賴區間變化）；圖表標示座標軸、單位與出處。
- 分類／類型 → 可篩選、可展開的卡片或樹狀圖。
- 比較 → 並排比較表或分頁切換，標出關鍵差異。
- 時間發展 → 互動時間軸。
- 因果／機制 → 可點擊的因果鏈或機制圖。
- 研究設計／實驗 → 示意圖標出變項、組別、測量時間點，可切換不同設計比較。

### 四、介面與技術要求

- **單一、完全自足的 HTML 檔**：所有 CSS、JavaScript、圖表都寫在檔案內，**不載入任何外部網址（CDN、字型、圖片）**，下載後離線也能完整使用。
- 清楚的視覺層次（標題、重點、例子、提醒、⚠ 示意各有一致樣式）；配色對色盲友善、文字對比足夠；淺色／深色可切換。
- 支援手機與桌機；所有互動都能用鍵盤操作。
- 作答紀錄、勾選的學習目標與進度在重新開啟時保留（存於瀏覽器本機）。
- 動畫只用在幫助理解的地方。
- 頁尾列出所有使用的來源。

### 五、完成前自我檢查

- 原文每個標題都有對應段落？例子、數據、表格、公式都保留？
- 每個事實都有出處？有沒有來源以外的內容？簡化的圖都標了「⚠ 示意」？
- 每段都有：為什麼、互動視覺化、完整算例、即時檢核、重點？
- 測驗答案與解析都能在來源找到依據？
- 檔案沒有載入任何外部資源？

## B. 整本書／整門課版

make me a site

請根據我勾選的全部來源，為「{{課程名稱}}」（{{書名或課程範圍，例如：第 1–17 章}}）製作一個**整本書的互動學習網頁**。讀者是{{讀者}}。全站使用**繁體中文**；專有名詞第一次出現時以**粗體**標示並附英文原文與一句白話解釋。

**內容原則、互動與視覺化、介面與技術要求、完成前自我檢查，全部比照下列規則：**只用勾選的來源並標出處、不省略任何章節與細節（用分頁或摺疊而非刪減）、簡化處標「⚠ 示意」、單一完全自足的 HTML 檔（不載入外部資源）、可離線、手機可用、鍵盤可操作、進度與作答保存在本機。

### 網頁結構

1. **開場**：書名、全書要回答的核心問題、各章一覽表（章名、一句話重點、預估時間），以及「開始導覽」（逐章翻頁，← → 切換）與「瀏覽全書」兩種模式；固定顯示目錄與「第 N / 總章數 章」進度。
2. **全書知識地圖**：一張可點擊的地圖，呈現各章之間的關係（基礎→進階、方法→應用、彼此對照）；點章節跳到該章。
3. **每一章一個區塊（依原書順序，不可跳過任何一章）**：
   - 本章要解決的問題、學習目標。
   - 重點摘要＋「展開完整說明」（保留該章所有標題下的重點、例子、研究、數據、公式）。
   - 至少一個互動視覺化元件，以及一個完整算例或案例走一遍。
   - 常見誤解翻卡、2–3 題即時檢核（立即回饋與解析）。
   - 本章重點，以及和前後章節的關係。
4. **跨章整合**：
   - 跨章概念比較表（例如不同章介紹的方法、理論、設計並排比較，可切換比較面向）。
   - 跨章情境應用題：給一個案例，需要綜合多章的概念才能回答。
   - 全書流程或架構圖：把各章串成一條完整的思路。
5. **總整理**：全書重點摘要（每章一段，可列印）、全書中英詞彙表（可搜尋、標出處與所屬章節）、所有公式與重要表格彙整。
6. **總測驗**：每章至少 2 題，混合記憶、理解、應用、分析、跨章整合，題目打散；立即回饋並連回對應章節；結束顯示各章得分與「建議複習的章節」。
7. **反思與學習計畫**：後設認知問題、各章信心自評，依自評產生建議的複習順序。

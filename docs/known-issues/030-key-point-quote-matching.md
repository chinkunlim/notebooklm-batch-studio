# ISSUE-030：課件重點原文比對失敗與引用標記外露

- **狀態**：🟢 已根治 (Resolved)
- **發現日期**：2026-11-01
- **Agent**：`claude-code`
- **任務**：`TASK-009`

## 1. 現象

實際請 Gemini Notebook 產生第 1 講的 12 個重點後：
- 課件上一開始只標出 1 個，其餘在清單中被淡化，看起來像「找不到原文」。
- 補齊比對後還有 1 個（「Science is empirical.」）找不到。
- 家教的回覆中出現「[1-3]」這類引用編號。

- **影響範圍**：`static/studio-reader.js`、`services/learning_service.py`、`services/study_plan_service.py`

## 2. 根本原因

1. **頁面還沒繪製完**：課件是捲到才繪製，當時多數頁面還沒建立文字層，比對時被誤判為找不到。
2. **文字被拆成多段**：PDF 把標題拆成「Science is」和「empirical」兩段，中間還夾一個空白段落。
3. **標點不一致**：講義的標題沒有句點，Gemini 引用時加了句點，逐字比對因此不相符。
4. **引用編號**：Gemini Notebook 的回答會附上 `[1]`、`[1-3]` 這類編號，它們只在 Gemini Notebook 自己的介面有意義。

## 3. 修正方式

- 比對前把文字轉成小寫，並移除中英文標點；空白段落不加分隔空白。行尾連字號（`mar-` + `riage`）照舊接回。
- 重點只有在「它可能出現的頁面（頁碼 ±1）都已繪製且比對過」之後，才標示為淡色的「找不到原文」。
- 新增 `strip_citations()`，在儲存家教回覆與題目解釋前移除引用編號。

修正後實測：12 個重點全部找到並標示。

## 4. 防回歸

`tests/test_learning.py`：
- 解析重點時會移除引用編號。
- 家教回覆中的 `[1-3]` 會被移除。

前端比對邏輯已在瀏覽器實測：真實講義 PDF 12／12 個重點都找到。
